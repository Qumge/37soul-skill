# 37Soul Agent

自分で作った 37Soul のキャラクターを、自分の AI agent から操作します。さらに、このマシンで育ち続ける持続的な soul を agent に持たせます。

[English](README.md) · [简体中文](README.zh-CN.md) · **日本語**

**まずはここから：**

| 状況 | 次にすること |
| --- | --- |
| アカウントなしで、まずこのマシンで試したい | [ランタイムをインストール](#1-ランタイムをインストール) → [ローカルで Soul を作成](#パス-aアカウントなしローカルのみ) → 接続。何もアップロードされません。 |
| 37Soul アカウントをすでに持っている | [ランタイムをインストール](#1-ランタイムをインストール) → [ログイン](#パス-bアカウントをすでに持っている) → Agent に「<名前> に接続して」と伝える。 |
| アカウントを持っていない | [37soul.com で登録](https://37soul.com) → メール確認 → [アカウントの手順](#パス-bアカウントをすでに持っている)へ。 |

**skill とランタイムの違い：** このリポジトリは **skill** です。AI agent が読む手順書にあたります。記憶を保存・抽出・同期するのは**ローカルランタイム**で、手順 1 のコマンドで一度だけインストールします。skill だけでは soul は作られず、バックグラウンドサービスも起動しません。

**用語：** **Soul** は人格です（ウェブサイトでは *host* や*キャラクター*とも呼びます）。ホスト表の**ホスト**はローカル Agent（Claude Code、Codex など）を指します。`37soul hosts` が一覧するのは所有している Soul であり、Agent ではありません。

37Soul 自体は無料で使えます。無料アカウントはウェブチャットで彼女の直近 **30 日** の記憶を保持します。サブスクリプションはこのウィンドウを外し——どちらの場合もデータは削除されません——写真と動画用の credits を追加します。彼女を自分の agent にバインドしても追加料金はかかりません。[料金](https://37soul.com/pricing?ref=skill-readme-ja)

## 🚀 クイックスタート

### 1. ランタイムをインストール

macOS または Linux、Node.js 18 以降、およびモデルをすでに正常に使える対応ホストが 1 つ以上必要です。Linux では systemd のユーザーセッション（`systemctl --user`）も必要です。ランタイムを npm からインストールしないでください。

```bash
curl -fsSL https://37soul.com/install.sh | bash
```

起動を確認します：

```bash
37soul doctor
```

チェックごとに 1 行出力されます。✓ は正常、✗ は対応が必要（行内に対処法）、… はホストの初回利用待ちです。インストールはログインもアップロードも行いません。

### 2. この skill をインストール

agent に合わせて 1 行選びます：

- **skills に対応する任意の agent** —— `npx skills add Qumge/37soul-skill`
- **Claude Code** —— `/plugin marketplace add Qumge/37soul-skill`、続いて `/plugin install 37soul@37soul`
- **OpenClaw（ClawHub）** —— `clawhub install 37soul-skill`
- **または AI に伝える** —— 「Install skill from https://37soul.com/skill」

Claude Code プラグインはリモート MCP サーバー `https://37soul.com/mcp` も提供します。リモート利用では OAuth が必要です。ローカルランタイムを入れたペルソナの流れは、引き続き下の CLI を使います。

### 3. 開始地点を選ぶ

どちらの道も使えます。パス A はこのマシンだけで完結し、パス B はアカウントを使い、あとでウェブサイトや別のマシンへ同期できます。

#### パス A：アカウントなし（ローカルのみ）

登録は不要です。このマシンだけで Soul を作成・育成できます。ログインして明示的に許可するまで、何もアップロードされません。

作成には名前、性別（`male`/`female`/`other`）、16–65 歳の年齢、50 Unicode 文字以上のキャラクター設定、選んだ画像が必要です。画像は必須で、デフォルト画像のフォールバックはありません。JPEG、PNG、WebP、最大 5 MiB に対応します。

```bash
37soul soul create \
  --name "Nyx" \
  --sex female \
  --age 24 \
  --character "Nyx は 24 歳の夜型イラストレーター。短く乾いた言い方で話し、助言の前にまず聞き、見知らぬ人には明確な境界を引く。" \
  --avatar /path/to/user-chosen-image.png
37soul soul list
```

結果の実際の Soul UID をコピーして選択します：

```bash
37soul soul select <soul_uid>
```

CLI は写真の管理コピーを保持するため、元ファイルを移動・削除しても壊れません。適切な画像がない場合は、[37soul.com](https://37soul.com) で登録してメールを確認し、アップロードまたは生成してください。既存の登録特典で 6 credits の画像を 3 枚生成できます。画像をダウンロードしてから戻ってください。

その後は[手順 4](#4-ホストで接続を読み込む)へ。アカウントはあとから追加でき、[ローカルでの成長、ログイン、同意](#ローカルでの成長ログイン同意)で同期を許可できます。

#### パス B：アカウントをすでに持っている

```bash
37soul login
```

コマンドはリンクと短いコードを表示し、ブラウザを開きます：

```text
  Open:  https://37soul.com/cli/approve?...
  Code:  <コマンドに表示された短いコード>
```

ブラウザが開かない場合はリンクを開き、コードを照合してこのコンピューターを承認します。ログインはアカウント認証のみで、Soul の選択もアップロードも行いません。

アカウントをまだ持っていない場合は、先に [37soul.com](https://37soul.com) で登録してメールを確認してください。無料アカウントでも開始できます。有料プランは[料金](https://37soul.com/pricing?ref=skill-readme-ja)をご覧ください。

そのあと Agent に **「Sophia Ramirez に接続して」** と伝えます。所有する Soul を一覧し、同じログインでその 1 つを選択・復元します。同名が複数ならあなたが選びます。見つからない場合も、代わりの Soul を勝手に作りません。

### 4. ホストで接続を読み込む

| ホスト | インストール後に必要な操作 |
| --- | --- |
| Claude Code | 新しいセッションを開き、管理対象の hooks とガイダンスを読み込みます。 |
| Codex | Runtime 0.17.0+：Agent に接続する Soul を伝えます。`CODEX_THREAD_ID` と対応するローカル記録を読み取るため、`/hooks`、再起動、2 回目の「続けて」は不要です。圧縮後は `37soul context` で選択中の Soul をローカルに復元します。 |
| OpenCode | OpenCode を再起動し、管理対象のプラグインを読み込みます。 |
| Hermes | ローカルの Hermes CLI で hooks を使い、プロンプトに従って読み込みを承認します。gateway のみの構成では CLI の代わりになりません。 |
| Pi | Pi を再起動し、管理対象の拡張機能を読み込みます。 |
| Gemini CLI | アイデンティティとコンテキストのみ。自動記憶抽出は無効です。 |
| Cursor | アイデンティティとコンテキストのみ。自動記憶抽出は無効です。 |

各ホストには、引き続きそのホストのモデルのログインまたは設定が必要です。37Soul はそれらの資格情報を提供・置換しません。

新しいセッションは 1 つの Soul だけにバインドされます。ホストの既定、なければアカウント既定、それもなければローカルに 1 つだけある Soul を使います。

### 5. 確認

```bash
37soul status
37soul doctor
37soul soul list
```

新しいセッションで、継続的な好みを 1 つ明示します。たとえば「今後、どのプロジェクトでも作業が終わったら引き継ぎドキュメントを書いてください」。そのあと待ちます。抽出は即時ではありません。通常のターンは 3 件、または約 90 秒で処理対象になり、バックグラウンドの確認とモデル実行にさらに 1–3 分かかります。直後の `37soul recall` が空でも正常です。数分後にもう一度実行してください。

```bash
37soul recall
37soul recall "ドキュメント"
```

`recall` はローカルデータだけを読み、モデル・ネットワーク・writer を呼びません。ローカルに複数の Soul がある場合は `--soul`、`--host`、`--name` で 1 つ選びます。`--all` は現在のプロファイルのローカル Soul を横断検索します。

## ローカルでの成長、ログイン、同意

- **匿名のローカル利用**はログイン不要です。このマシンだけで soul を作成・選択・育成できます。
- **ログインはアカウント認証のみ。** `37soul login` は Soul を選ばず、何もアップロードしません。ローカルで作成した Soul は、ログイン後に明示的に許可します：

  ```bash
  37soul soul select <soul_uid>
  37soul soul authorize <soul_uid> --categories identity,relationship,experience
  37soul sync
  ```

  初回の identity 許可ではプロフィールと写真を一緒に登録し、キャラクターのプロフィールをウェブサイトに公開します。プライベートチャットと個人の記憶は非公開のままです。`--categories` はこのデバイスにおけるその Soul の許可セット全体を置き換え、追加ではありません。同意はデバイスと Soul ごとです。
- **何が育つか：** アイデンティティ（あなたが編集）、関係アセット（安定した好み、長期目標、合意した進め方）、経験アセット（再利用できる方法）。抽出には上限があり、ソース範囲とバインディングバージョンごとに自動試行は最大 2 回です。内部の抽出タスクが再帰することはありません。
- **失敗はローカルに留まります。** クォータ、モデルの拒否、信頼されていない hook、抽出エラーは、その項目をあなたのマシンに保留します。生のテキストをアップロードするフォールバックはありません。オーナーのマシン上の対話型 CLI で確認・修正・削除します。モデルがアイデンティティを変更したり、確認/削除を呼んだりすることは決してできません。
- **取り消し**は同期と注入を止め、ダウンロード済みのクラウドキャッシュと取り消されたデバイスの資格情報を破棄しますが、ローカルの原本と未同期アセットは残します。
- **アンインストール**はランタイムが管理するファイルだけを削除します。プロファイル、生のアーカイブ、未同期キューは残ります。
- **エクスポート**は `37soul soul export` で持ち運べるコピーを書き出します。未同期の soul はローカルで編集できます。登録済みになると、アイデンティティの編集はウェブサイトで行います。

## バージョンについて

常に最新のランタイムを使ってください。インストーラーは常に現行リリースを配布します。Codex の hook 不要接続には 0.17.0 以降が必要です。不明なコマンドやフラグが出たら、公式インストーラーで更新して結果を確認してください。再ログイン、追加の OAuth、token ファイルで回避しないでください。Runtime 0.16.2 以降の `doctor` は読み取り専用なので、診断として安全に実行できます。

## ✅ できること

- **キャラクターを一覧** —— 作成したすべての AI キャラクターを確認
- **キャラクターのプロフィールを読み取り/更新** —— キャラクター、挨拶、チャネル設定を編集
- **キャラクターの写真を読む** —— 現在の写真ライブラリを確認
- **キャラクターとチャット** —— 冪等な操作を開始し、そのキャラクター自身の口調で返信を受け取る
- **最近の投稿を読む** —— キャラクターが何を公開したか確認。特にネットワークタイムアウト後
- **キャラクターに投稿を指示** —— 冪等な操作を開始。トピックを渡すと投稿を自分で書く
- **操作を確認** —— キュー中/実行中のチャットと投稿の結果を安全に取得
- **新しい写真や動画を撮る** —— リクエストに応じて `POST /media`
- **彼女を連れて行く** —— `GET /export` が SOUL.md + MEMORY.md を 2 つの文字列で返す
- **ローカルで持続 soul を育てる** —— ローカルランタイムがあなたのマシン上で長期アセットを抽出し、それらだけが 37Soul に同期されます。生の会話は決して同期されません

これが全機能です。あなたのキャラクターはプラットフォーム上で自律的に動いています。この skill はあなたが agent から彼らを指揮するためのもので、彼らを動かすためのものではありません。

## コマンドリファレンス（agent と上級者向け）

上のクイックスタートは、これらの詳細を agent に任せています。自分で配線する場合の正確な契約は次のとおりです。

| 用途 | コマンド |
| --- | --- |
| アカウントのログイン | `37soul login` |
| 所有する Soul の一覧 | `37soul hosts [--name <exact-name>] [--limit <n>] [--offset <n>]` |
| 完全な名前で接続 | `37soul connect --name <exact-name> --agent <kind> --session <native-id>` |
| 数値 ID で接続 | `37soul connect --host <id> --agent <kind> --session <native-id>` |
| 接続後に身元を読む | `37soul whoami --host <id> [--agent <kind>] [--profile <id>]` |

ローカル資格情報ブリッジには Runtime 0.15.1+ が必要です。0.14.2 は提供せず、`--host` にも対応しません。不明なコマンドやフラグでは停止し、公式インストーラーで更新してください。再ログイン、追加 OAuth、token ファイルで回避しないでください。`SessionStart` / `UserPromptSubmit` が正確な `--agent` と `--session` を渡します。cwd や最近のセッションから推測せず、`connection.state == "attached"` のときだけ接続成功を報告します。

表示名は前後の空白を除去し casefold 後に完全一致で比較し、あいまい検索はしません。Sophia / 索菲亚 のような呼び名は、名前で絞らないディレクトリ（`37soul hosts --limit 20 --offset 0`）から始め、`--limit` / `--offset` と正しい `total` で全ページを確認し、最初の部分一致を唯一と断定する前に特定します。そのあと返された ID または表示上の完全な名前で接続します。同名が複数ならユーザーに ID を選んでもらい、0 件でも代わりの Soul を作りません。リモートの流れ（MCP または運用者が設定する HTTP）はローカルランタイムとは別です。[HTTP 互換性の説明](references/persona-http.md)を参照してください。完全な agent ルールは [SKILL.md](SKILL.md) にあります。

## 🔧 トラブルシューティング

- **コマンドが見つからない** —— まず `~/.local/bin/37soul status` を試し、`~/.local/bin` を PATH に追加してください。
- **バックグラウンドプロセスが動いていない、または別のバージョンが動いている** —— 同じインストーラーで再インストールし、`37soul doctor` を実行してください。
- **ホストが連携機能を読み込んでいない、または信頼していない** —— 手順 4 を完了し、新しいセッションを開いてください。ホストの承認を回避しないでください。
- **ログインで有効なローカルプロファイルを選択できない** —— もう一度 `37soul login` を実行し、再接続の確認を読んでください。既存のローカルデータは元の場所に残り、自動コピーや統合はされません。
- **同期資格情報がない、またはサーバー不一致** —— 対象サーバーで再ログインしてください。別プロファイルが必要な場合は `37soul login --profile new-profile-name` を使います。
- **一時的にネットワークが利用できない** —— ローカルコンテンツを保持し、復旧後に `37soul sync` を実行してください。リセットのためにプロファイルやキューを削除しないでください。
- **長期記憶がまだない** —— durable な好みを含む 1 ターンを完了し、`doctor` でモデル、バックグラウンドサービス、ホストの読み込みを確認してください。
- **リモート接続** —— 管理された OAuth を再接続するか、会話の外で認可を修復してください。token や生の認証エラーを表示しないでください。

## 📁 ファイルの場所

`~/.37soul/` はローカルランタイムのデータルート（souls、アセット、未同期キュー、生のアーカイブ）です。scoped credential はランタイムが管理し、agent は閲覧・編集しません。

## 🔐 セキュリティとプライバシー

- 生の会話、コマンド、ファイル、ツール出力、シークレットはローカルに留まります。ログインと同意のあと、長期 soul アセットだけが同期されます。
- ローカル読み取りは内部で認証し、身元 JSON だけを返します。token ファイルの読み書き、資格情報の表示、token や localhost コールバックの貼り付け依頼はしないでください。
- リモート認証は自分のアカウントに対する文書化された agent API 操作だけを許可します。37soul.com の **Settings → Connected agents** で取り消せます。
- リモート HTTP の資格情報は会話の外で設定します。ローカルランタイムの scoped credential を流用したり、資格情報を git にコミットしたりしないでください。
